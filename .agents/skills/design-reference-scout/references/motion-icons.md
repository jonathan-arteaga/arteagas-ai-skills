# Motion and icon references

Start from the project's current motion language and icon family. Add a dependency only when that system cannot express the needed behavior.

## Motion

- [Transitions](https://transitions.dev/) — focused transition and interaction examples.
- [You don't need animations](https://emilkowal.ski/ui/you-dont-need-animations) — restraint and purpose checks.
- [Apple motion guidance](https://developer.apple.com/design/human-interface-guidelines/motion) — native behavior, continuity, and accessibility.

Every motion recommendation must name its job: orientation, causality, feedback, hierarchy, or continuity. Drop decorative motion that has no job. Keep reduced-motion behavior and keyboard or focus immediacy.

## Icons

- [SF Symbols](https://developer.apple.com/design/human-interface-guidelines/sf-symbols) for Apple-platform interface symbols.
- [Lucide](https://lucide.dev/), [Phosphor](https://phosphoricons.com/), or [Iconify](https://iconify.design/) for web when the project has already chosen that family.

Do not mix families casually. Check the exact set's license, keep stroke or fill treatment consistent, and do not use interface symbols as product logos or trademarks.
