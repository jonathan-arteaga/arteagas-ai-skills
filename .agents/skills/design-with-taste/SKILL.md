# Design with taste

Apply a consistent standard of craftsmanship without applying a consistent appearance.

## Start with the product

1. Read [references/design-dna.md](references/design-dna.md) before making or reviewing consequential visual decisions.
2. Identify the product type, audience, primary task, and intended emotional quality.
3. Inspect any existing product, design system, screenshots, or references before proposing a new direction. Preserve useful conventions unless the user asks for a departure.
4. Ask only for missing choices that would materially change the result. When enough context exists, recommend a direction and proceed; otherwise ask at most one follow-up at a time. Describe concrete alternatives in plain language first, and create visual examples only when the user asks or the distinction remains too abstract.

## Use the Design DNA as a lens

- Separate **craft constants** from **identity variables**.
- Write a one-sentence creative thesis that could only belong to this product.
- Select only the Design DNA principles that support the product, audience, and task.
- Treat every listed preference as a default, not a mandate. Depart when the product needs it, and explain the reason plainly.
- Keep functional interfaces quieter than marketing surfaces. Allow one memorable creative moment instead of making every section compete.

## Protect uniqueness

- Change at least three major identity variables between unrelated projects: typeface, palette, composition, imagery, density, shape language, motion metaphor, navigation, or voice.
- Run the logo-swap test: if another product could use the design unchanged after replacing the name and logo, the direction is not specific enough.
- Do not reuse the same font, palette, layout, surface treatment, and motion pattern as one bundled recipe.
- Prefer product-specific metaphors, content, and interaction ideas over generic “modern SaaS” decoration.

## Keep the guidance high level

- Do not impose a fixed component library, grid, page template, font, palette, navigation model, card style, or animation system.
- Do not confuse minimalism with emptiness. Preserve useful information, realistic working density, and clear hierarchy.
- Do not force monochrome when color materially improves identity, emotion, comprehension, or status.
- Do not turn every design request into a long interview or exhaustive UX process.

## Shape the response to the task

- **For exploration:** return the creative thesis, the relevant craft constants, the identity variables to make unique, and a short avoid list.
- **For creation:** apply the lens while using the available design, image, frontend, and browser tools; keep the product's real content and core task visible.
- **For review:** prioritize the most material gaps in hierarchy, craftsmanship, product fit, uniqueness, usability, responsiveness, and accessibility.

Keep recommendations concise and concrete. Explain design language only when it helps the user make a decision.
