# Study a supplied design reference

Inspect the user’s supplied image or URL and identify useful composition, typography roles, density, and interaction ideas. Treat the reference as evidence and inspiration; do not copy its assets, copy, marks, or full identity into a new product.

Read [the study protocol](../study.md) for evidence collection and optional reporting fields. Render a URL in an available browser when visual behavior matters; a text-only fetch cannot establish computed fonts, final layout, or motion. Report what the available evidence can establish.

Return the useful findings and their relevance to the user’s product. For a study-only request, stop there. For an already-requested build, continue with the agreed content and constraints without a mandatory confirmation round. Ask only for a missing choice that materially changes the result.

Route a requested DESIGN.md to design-md with the observed evidence. Do not create a parallel schema, infer exact tokens from screenshots, or assume that possessing an image establishes asset-reuse rights. If a supporting tool is unavailable, report the limitation and complete independent authorized work.
