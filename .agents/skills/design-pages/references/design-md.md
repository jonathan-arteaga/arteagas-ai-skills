# Hand off design documentation

Use when the user asks to document, lock, extract, or update the design system in `DESIGN.md`. The `design-md` skill owns the format, evidence rules, and validation. This reference defines the handoff only; it has no independent document template.

- Pass the selected product, current design decisions, governing tokens/components, relevant consumers, and any existing document. Source-backed intent can govern; a suggested palette or screenshot guess cannot become an exact normative token.
- For a public URL, let `design-md` apply its rendered evidence pipeline and reconstruction limits. Study notes can help select observations; they do not replace measurement.
- For screenshot-only study, preserve the qualitative diagnosis and identify the source/rendered evidence needed for documentation. Do not turn estimated colors or candidate fonts into exact tokens.
- Read the resulting document on future page work. If an authorized change affects its decisions, hand the verified change back to `design-md`; do not append an ad hoc Variants, Provenance, or Exports section.
- Do not require a document for ordinary page work or create one as a side effect of a multi-page redesign. Continue independent authorized implementation when the documentation handoff cannot run, and state the limitation.
